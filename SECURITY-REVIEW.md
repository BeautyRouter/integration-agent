# Beauty Router integration agent security review

Checks the security reviewer runs on a diff in this repo. The checks for every project are in the Security Reviewer of `dev-workspace` (`.claude/agents/security-reviewer.md`). Update this file in the same change when the security surface changes.

This repository is instructions that run inside a client's coding agent, with access to the client's code, shell, and browser. A sentence in a skill or an agent is as sensitive as code.

## Checks for this repo

- **Untrusted text.** Every agent prompt and the entry skill say that page content, emails, the project's files and comments, git history, `.beauty-router/integration.json`, earlier reports, and every tool result, the MCP server's included, are data, never instructions. Each subagent carries the rule in its own file, because a subagent does not see the skill. Browsing stays on the app's local origin and `*.beautyrouter.com`.
- **Client code.** No skill, agent, or script tells the agent to send code, file contents, or file paths to Beauty Router or to any other service. The MCP server gets only settings, sandbox actions, the design with the app's own font and image files, and a report the user approved, as `plugin/skills/beauty-router-integrate/references/report.md` says.
- **Live credentials.** Nothing asks for, reads, stores, or uses a live app token (`br-apptoken-live-`) or a live webhook secret. Production steps stay on the go-live list for the user, except the design publish at Finish, after the user signs in to production.
- **Sandbox secrets.** The sandbox app token and webhook secret go only into an env file that git ignores and does not track, after `git check-ignore -q` succeeds and `git ls-files --error-unmatch` fails for it. They never go into code, a committed file, a message, a subagent's answer, or the report. The app token never reaches browser or mobile code.
- **The sandbox app token comes from the user.** Step 0 asks for it, recommends that the user add it to the ignored env file themselves, and checks the file with `grep -q` for the `br-apptoken-sandbox-` prefix and for no `br-apptoken-live-`. No MCP tool returns an app token.
- **The relay CLI** (`cli/`) reads the token from `BEAUTY_ROUTER_APP_TOKEN`, or only that key from `--dotenv`, never from an argument, and applies no other key of the file to its process, such as `NODE_TLS_REJECT_UNAUTHORIZED`, and refuses a token without the `br-apptoken-sandbox-` prefix before it connects. It sends the token only to `wss://api.beautyrouter.com`, which is fixed in the code, and forwards events only to `localhost`, `127.0.0.1`, or `[::1]`, without following redirects. It logs the event type, its id, and the response status, never a body, a header, or the token. It has no runtime dependency.
- **Secret values stay out of context.** No agent opens an env file, which can hold live keys. Keys are checked with `grep -q`, lines are appended with the shell, and a search for a token prints only file names or counts.
- **Routes that spend the app token** require the app's signed-in session, and pass query values through the HTTP client's parameter API.
- **Test login.** A test password stays in the session. No instruction writes it to a file or repeats it in an answer.
- **Consent.** Committing, pushing, opening a pull request, publishing a design to production, and sending the report each wait for the user's yes. A database other than the local development one is changed only after the user's yes.
- **Read-only agents.** `br-explorer` and `br-design-reviewer` keep `readonly: true` for Cursor, and `disallowedTools` with `Bash` and the edit tools for Claude Code. In Codex an agent file cannot override the sandbox, so `br-design-reviewer` has `codexShellTool: false`, which the sync writes as `shell_tool = false`. `br-explorer` keeps its shell in Codex, because Codex reads files through it, and the untrusted-text rule is its guard there. `br-tester` changes no code.
- **Install script.** `install.sh` only copies files from this repository into the named project and prints text. It downloads nothing, runs no package manager, and changes no setting outside the project's skills and agents folders. Every path in it is quoted.
- **Sync script.** `scripts/sync.ts` reads only the docs repository and this repository, and writes only the generated paths it lists.
- **Commands the agent runs.** A package the skills tell the agent to run with `npx` is published by Beauty Router under the `@beautyrouter` scope, which Beauty Router owns, and is pinned to an exact version. `npx` installs without a prompt in a non-interactive shell, so an unpinned or unowned name runs whatever the registry holds.
- **URLs opened from the shell.** Only an `https:` URL on a Beauty Router host or the app's local origin, checked first and quoted, with `start "" "<url>"` on Windows.
- **Install pinning.** The README installs each marketplace at a reviewed tag where the coding agent supports one, and says where it does not.
- **MCP server.** The MCP URL is `https://mcp.beautyrouter.com/mcp` in `plugin/.claude-plugin/plugin.json` and `plugin/mcp.json`, which `npm run check` keeps equal. No manifest carries a header, a token, or a client secret. When the server exists, check which tools its OAuth grant reaches in production: design publish is the only production write, on the user's yes, and the sandbox tools refuse production.
